# nntrainer: causal attention учитывает будущие значения

7 сентября 2026 года на актуальном публичном `main` nntrainer
`a7ea056e79ab8e14447ea305c1b634e233343258` воспроизведено нарушение causal-маски.
Это один отчёт о реализации `AttentionLayer` с тремя механизмами отказа.
Локальное исправление проходит **42 теста**; исходная версия — **21 из 42**.
Четыре ключевых случая воспроизводятся одинаково в трёх свежих процессах.

## Минимальный случай

```
causal_mask=true, scaled_dot_product=false
Q shape = [1,1,2,1], Q = [0,0]
K shape = [1,1,3,1], K = [0,0,0]
V shape = [1,1,3,1], V = [2,10,50]
```

| Проверка | Исходная C++-реализация | Математический результат / после патча |
|---|---|---|
| Выход | `[20.66666794,20.66666794]` | `[2,6]` |
| Производная первого выхода по V | `[1/3,1/3,1/3]` | `[1,0,0]` |
| Замена будущего V₂=50 на −100 | Изменяет ранние выходы | Не влияет на них |

Матрица QKᵀ здесь нулевая. Для запроса с индексом i допустимы только ключи
с индексами j≤i. Поэтому первый выход равен V₀=2, а второй — (V₀+V₁)/2=6.
Будущий V₂ не участвует ни в одном выходе. Такая трактовка продолжает
верхнетреугольную causal-маску существующего квадратного случая; отдельного
смещения для rectangular cross-attention публичный `forwarding` не принимает.

Результат получен вызовом нативного слоя, а не Python-переписыванием библиотеки.
Код: [attention_regression.cpp](attention_regression.cpp).

## Причины и исправление

1. В `forwarding` создаётся квадратная маска Nk×Nk, хотя scores имеют форму
   Nq×Nk. При Nq≠Nk `Tensor::add_i` возвращает ошибку несовместимых форм;
   вызывающий код её игнорирует. Softmax затем вычисляется без маски.
2. Даже в квадратном случае вычитание конечной константы `1e10` не исключает
   будущий ключ. При Q=[1,1], K=[0,2e10], V=[2,10] первый выход равен 10 вместо 2.
   Все эти входы и соответствующие logits конечны в FP32.
3. `incremental_forwarding` применяет маску только при `from=0`. В последующем
   многотокенном блоке ранний токен видит более поздние токены того же блока.
   При Q=K=[0,0,0], V=[2,10,50] полный проход даёт [2,6,20.6667],
   а блоки [0,1) и [1,3) — [2,20.6667,20.6667].

Патч непосредственно записывает −∞ только в запрещённые элементы scores.
Границы берутся из фактической прямоугольной формы, а incremental-путь учитывает
абсолютное смещение `from`. Это сохраняет точный ноль вероятности будущего ключа,
избавляет от отдельного буфера маски и от игнорируемого broadcasting-error.
На каждой проверенной строке есть хотя бы один разрешённый конечный logit.

## Проверка

- 28 новых тестов и 14 существующих attention semantics/golden тестов.
- FP64-эталон отдельно суммирует только разрешённые ключи и вычисляет выход,
  dQ, dK, dV. 16 сочетаний прямоугольной/квадратной формы, batch=1/2,
  scaled/unscaled; абсолютный допуск 3e−5.
- Независимые батчи дают те же выходы и градиенты, что совместный батч.
- V=I позволяет прочитать вероятности: диапазон [0,1], сумма 1,
  точный ноль за causal-границей.
- Центральные разности фактического C++-forward по Q/K/V, шаг 1/256,
  допуск 2e−4; сверяются и с backward, и с математическим эталоном.
- Восемь разбиений пяти токенов, включая одиночные шаги и несколько
  многотокенных блоков, совпадают с полным математическим вычислением.
- До: 21 failed / 21 passed. После: 42 passed. Четыре минимальных случая
  повторены в трёх отдельных процессах для каждой версии.
- Патчи применены к чистым копиям точных pinned-файлов; результат побайтно
  совпал с проверенными исходниками. Изменённые C++-файлы отформатированы
  clang-format 14; `git diff --check` проходит.
