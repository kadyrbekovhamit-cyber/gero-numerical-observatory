# nntrainer: неверный градиент LayerNorm при affine-параметре gamma

Проверено 7 сентября 2026 года. В реальной C++-реализации nntrainer подтверждён
дефект обратного прохода LayerNorm: градиент входа не учитывает `gamma` на
проверенных формах. Локальное исправление проходит все 42 проверки; исходная
реализация — 22 из 42. Точного дубликата в проведённом публичном поиске не найдено.
Подтверждения от разработчиков пока нет.

Это результат тестирования открытой библиотеки nntrainer. Он не устанавливает
наличие ошибки в конкретном устройстве или коммерческом продукте Samsung.

## Минимальный пример

Проверенный исходник:
[nntrainer a7ea056, LayerNormalizationLayer::calcDerivative](https://github.com/nntrainer/nntrainer/blob/a7ea056e79ab8e14447ea305c1b634e233343258/nntrainer/layers/layer_normalization_layer.cpp#L263).
Этот commit совпадал с публичным `main` при проверке.

```
shape = [1, 1, 1, 4], normalized axis = 3
x     = [-1, 0, 1, 2]
gamma = [ 1, 2, 4, 8]
beta  = [ 0, 0, 0, 0]
dy    = [ 1, 1, 1, 1]
epsilon = float32(1e-5)
objective = sum(LayerNorm(x, gamma, beta))
```

| Метод | Градиент по x |
|---|---|
| Исходная C++-реализация | `[0, 0, 0, 0]` |
| Аналитическая формула FP64 | примерно `[0.62607184, -0.53666240, -0.80497302, 0.71556358]` |
| Конечные разности фактического forward | `[0.62604523, -0.53656006, -0.80487061, 0.71552277]` |
| C++ после локального исправления | `[0.62607181, -0.53666240, -0.80497301, 0.71556360]` |

Конечные разности используют шаг `1/256` и вызовы самой библиотеки с
возмущённым входом. Это независимая проверка аналитического эталона.
Разница исходного результата с эталоном достигает около `0.805` на обычных числах.

Ещё один инвариант: если весь `gamma=0`, выход равен `beta` и не зависит от входа.
Следовательно, `dx=0` для любого входящего градиента. Исходная версия нарушает
это свойство, исправленная его соблюдает. Контроль с `gamma=1` проходит в обеих
версиях.

## Математика и причина

Для одной группы нормализации определим:

```
d = x - mean(x)
v = mean(d*d) + epsilon
r = 1/sqrt(v)
g = dy * gamma
dx = r * (g - mean(g) - d * mean(g*d)/v)
```

Умножение на `gamma` должно предшествовать обоим усреднениям. Исходный код
сначала делает усреднения `dy`, затем пытается умножить сокращённый тензор
`inv_std_dev` на `gamma` на месте. Их формы несовместимы для поддерживаемого
библиотекой направления broadcasting. `Tensor::multiply_i` ловит исключение и
возвращает код ошибки, который вызывающий код не проверяет. В результате
`gamma` не применяется.

Исправить только broadcasting недостаточно: применение различающихся
коэффициентов после усреднений всё равно дало бы неправильную производную.
Патч сначала вычисляет `g=dy*gamma` в полноразмерном тензоре и затем делает
редукции. Он использует существующие временные буферы; вычисление градиентов
`gamma` и `beta` сохранено. Кэшированные `deviation` и `inv_std_dev` теперь
не перезаписываются обратным проходом.

## Что проверено

- Реальная нативная C++-библиотека, FP32, CPU, NCHW; macOS 15.5 arm64, Apple M4.
- 24 новых теста: 14 комбинаций семи наборов осей и trainable/frozen режима,
  аналитические значения и производные, конечные разности входа и весов,
  нулевой/постоянный/неодинаковый `gamma`, постоянный вход и epsilon,
  независимое разбиение батча, эквивалентная форма независимых групп и сдвиг входа.
- 18 существующих тестов nntrainer для LayerNorm: 11 semantics и 7 golden.
- До исправления: **20 failed, 22 passed**. После: **42 passed**.
- Четыре ключевых теста повторены в трёх отдельных процессах для каждой версии;
  результат и значения градиента воспроизводятся.
- Оба изолированных патча применены к копиям файлов из точного pinned commit;
  результат побайтно совпадает с проверенными исходниками.

Новые тесты используют FP64-эталон из округлённых FP32-входов. Типовой допуск:
`3e-5 + 3e-5*abs(expected)`; у минимального примера абсолютный допуск `2e-6`.
Для конечных разностей фактического FP32-forward допуски отдельно заданы
`5e-4` и `1e-3`. Число тестов не является оценкой распространённости дефекта.
