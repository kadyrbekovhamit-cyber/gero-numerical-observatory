# Продукт и UX gero.uz

## Главные сценарии

ML-инженер проверяет, затронут ли его operator/dtype/provider, и скачивает минимальный граф. Data scientist смотрит, соблюдает ли метрика ожидаемый контракт и как выбрать допуск. Автор runtime изучает входы, actual/reference outputs, версию ONNX и воспроизводит случай одной командой.

Основной путь: **каталог → фильтр → наблюдение → тестовый граф → воспроизведение**. Регистрация не нужна для чтения публичных результатов и загрузки синтетических тестов. Находки показываются вместе с границами вывода; значок статуса всегда сопровождается текстом.

## Информационная архитектура

| Раздел | Что инженер получает | Реализовано |
|---|---|---|
| Reports | Поиск, category/dtype/optimization/status, сортировка, страницы по 12 строк | Да |
| Observation detail | Контракт, ошибки abs/rel/ULP, число нарушений, environment, ZIP/ONNX/NPZ, replay | Да |
| Benchmarks | Доли исходов по операциям, переход к соответствующим строкам, таблица измеренного времени | Да |
| Methodology | Математические условия, epsilon, маски, исключения, ссылки на спецификацию | Да |
| Version comparison | Выбор двух совместимых runs и история изменений | CLI baseline реализован; UI timeline — следующий этап |
| Candidate registry | Несколько наблюдений одного расследования, duplicate links, upstream status | Поля/архитектура спроектированы; редакционная БД не реализована |

Фильтр backend в текущем UI не нужен: пара всегда ONNX Runtime / ONNX ReferenceEvaluator. Фильтр provider также не имитируется: весь запуск CPU. После добавления других исполнителей эти facets появляются из реальных метаданных.

## Визуальный язык

Тёплый светлый фон, тёмно-зелёный основной цвет, терракотовый цвет расхождений. Спокойная типографика интерфейса, моноширинные числа и identifiers, акцентный serif только в заголовке. Таблица имеет приоритет над декоративными диаграммами. Показатели первого экрана вычисляются из JSON, а не зашиты в макет.

В колонке ошибки не показывать `0`, если сравнение не имело конечных пар; выводить «Non-finite» и подробную диагностику в карточке. ULP — диагностическое расстояние, а не универсальный pass/fail-порог. Максимальная относительная ошибка около нуля может быть очень большой, поэтому абсолютный допуск и исходные значения доступны рядом.

## Взаимодействие

Поиск по имени операции/варианту/hash (точная операция: `op:Softmax`), URL сохраняет фильтры и observation ID. Ссылку можно передать коллеге и открыть в том же состоянии. Reset filters, явное empty state и сообщение о невозможности загрузить данные. Slash фокусирует поиск; Escape закрывает native dialog. Карточка показывает нарушенные проверки первыми. Download-кнопки ведут только к реально экспортированным файлам; копирование команды сообщает об успехе или предлагает выделить текст.

Диаграмма Benchmarks представляет количество наблюдений, не достоверность библиотеки. Click по сегменту показывает соответствующие записи. Latency — median of per-case medians; метод, число измерений и архитектура явно видимы. Смешение синтетических размеров, interpreter overhead и runtime не превращается в рейтинг реальных моделей.

## Адаптивность и доступность

При узкой ширине навигация переносится на отдельную строку, summary располагается в 2 колонки, формы фильтров переносятся, таблица прокручивается в собственном контейнере. Диалог ограничен шириной viewport. Используются семантические heading/table/button/link, labels для controls, skip link, focus-visible, aria-live для количества результатов, текстовые статусы и reduced-motion. Проверка браузером — функциональный smoke test, не формальная accessibility certification.

Английский выбран для международной технической аудитории и совместимости названий ONNX. Документация проекта — по-русски. Русская и узбекская версии интерфейса требуют полного перевода методологии, статусов и empty/error states; частичное переключение только заголовков не планируется.

## Размещение в существующем GERO

Сохранить текущее содержимое сайта и добавить отдельный раздел `/stability/`. В основной навигации — Numerical Observatory, в публикациях — ссылки на observation/candidate, в каждой карточке — исходная публикация при её появлении. Существующий математический demo не выдаётся за ONNX runtime. Публичные отчёты получают постоянные IDs и версионированные URLs; текущая версия прототипа работает с одним экспортированным run.
